# MCP-интеграция Mac Coffee

[English](MCP.md) · **Русский** · [简体中文](MCP.zh-Hans.md)

Direct-сборка Mac Coffee содержит локальный MCP-сервер для Codex, Claude Desktop и других stdio-клиентов. Интеграция опциональна, по умолчанию выключена и полностью отсутствует в Mac App Store-сборке.

## Быстрая настройка

1. Установите и запустите Direct-сборку Mac Coffee.
2. Откройте **Настройки → ИИ и автоматизация**.
3. Включите MCP.
4. Откройте мастер настройки клиента.
5. Выберите Codex, Claude Desktop или Generic stdio.
6. Проверьте путь к конфигурации, путь к встроенному helper и точный diff.
7. Подтвердите установку и перезапустите MCP-клиент.
8. Выполните первый запрос и подтвердите сопряжение в Mac Coffee.

Мастер сохраняет посторонние настройки, проверяет итоговый файл и создаёт резервную копию перед заменой. Если файл повреждён, содержит конфликт, является symlink или недоступен для безопасной записи, Mac Coffee показывает ручную инструкцию и не изменяет оригинал.

## Конфигурация клиентов

В стандартной установке MCP helper находится здесь:

```text
/Applications/Mac Coffee.app/Contents/Helpers/MacCoffeeMCP
```

Если приложение находится в другом каталоге, используйте путь из мастера.

Codex получает запись в `~/.codex/config.toml`:

```toml
[mcp_servers.mac_coffee]
command = "/Applications/Mac Coffee.app/Contents/Helpers/MacCoffeeMCP"
```

Claude Desktop получает объект `mac-coffee` в `~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "mac-coffee": {
      "command": "/Applications/Mac Coffee.app/Contents/Helpers/MacCoffeeMCP",
      "args": []
    }
  }
}
```

Для другого клиента добавьте локальный stdio-сервер с этим executable и пустым списком аргументов. Mac Coffee должен быть уже запущен: helper намеренно не запускает приложение.

## Инструменты и ресурсы

Доступны инструменты `maccoffee_get_status`, `maccoffee_set_session`, `maccoffee_stop_session`, `maccoffee_set_battery_threshold`, `maccoffee_set_launch_at_login` и `maccoffee_set_language`.

Для `maccoffee_set_session` режим принимает `system` или `display`, а длительность — `minutes30`, `hours1`, `hours2`, `hours4`, `hours8` или `indefinite`. Порог батареи ограничен 10–30%. Язык принимает `system`, `en`, `ru`, `de`, `fr`, `zh-Hans`, `ja`, `ko` или `es`.

Изменяющие вызовы могут содержать `requestId` длиной до 128 символов. Повтор запроса от того же клиента возвращает сохранённый результат и не применяет действие второй раз.

Ресурсы:

- `maccoffee://status` — текущее состояние приложения;
- `maccoffee://capabilities` — возможности и версия контракта;
- `maccoffee://activity` — ограниченный журнал локальной активности.

Подписка на изменения статуса поддерживается.

## Безопасность

- MCP работает только после явного включения пользователем.
- XPC ограничен текущим пользователем macOS; broker проверяет расположение и подпись executable.
- Новый клиент проходит P-256 challenge-response и требует подтверждения в приложении.
- Незавершённые challenge истекают через 120 секунд; количество challenge, ожидающих подтверждения клиентов и записей защиты от replay жёстко ограничено.
- Доверие и ключи хранятся в Keychain и привязаны к code identity клиента.
- Доступ можно немедленно отозвать или полностью забыть в настройках.
- MCP не обходит защиту аккумулятора и системные решения macOS.
- Журнал ограничен, хранится только в памяти и очищается при завершении Mac Coffee.
- App Store-сборка не содержит MCP-артефактов или MCP-символов.

## Неполадки и удаление

Если клиент сообщает, что приложение недоступно, запустите Mac Coffee, проверьте статус Ready и повторите мастер после перемещения приложения. Если требуется approval, подтвердите ожидающий запрос в настройках. После обновления и смены code identity заново выполните сопряжение.

Для удаления выключите MCP, удалите таблицу `mac_coffee` из Codex или объект `mac-coffee` из Claude Desktop, перезапустите клиент и при необходимости забудьте доверенные записи в Mac Coffee.
